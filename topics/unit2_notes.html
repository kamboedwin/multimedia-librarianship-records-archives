Digital Media Fundamentals and Visual Communication

Understand how pixels, colour, typography and layout influence readable, trustworthy multimedia materials.

Start here: a familiar situation

Imagine enlarging a tiny catalogue picture until the letters look blocky. Now imagine the same words written as a scalable vector diagram: the edges can remain sharp. Both images appear on a screen, but they are represented differently. Visual communication also depends on whether people can read the text, recognise what matters first and distinguish foreground from background.

Key words in simple language

  • Pixel: one picture element in a raster image grid.
  • Raster image: a picture represented by a grid of pixels.
  • Vector graphic: a graphic represented through shapes, paths and mathematical descriptions.
  • Contrast: the difference in brightness or colour that helps distinguish content.

Think about it: Why might a large, attractive poster still be difficult to use? The sections below explain how to answer this question.

For other terms, see the course multimedia glossary.

Learning outcomes. After studying this unit, you should be able to (1) explain raster/vector representation and image dimensions; (2) distinguish pixels, PPI and DPI; (3) estimate uncompressed image data size; (4) explain colour models, bit depth and colour management; (5) apply hierarchy, typography, alignment and contrast; (6) evaluate visual designs for BLISS and BRIM audiences.

2.1 Why digital media fundamentals matter

A digital library banner, a photograph of an archival document, a diagram explaining a records workflow and an information poster may look like ordinary images to a user. Behind each is a series of technical and design decisions. How many pixels are available? What happens when a small image is stretched? Will its colours look acceptable on another screen or in print? Can a person read the labels on a mobile phone? Does the visual preserve the meaning and context of its source?

Digital media fundamentals describe how media are represented, stored and displayed. Visual communication concerns the arrangement of text, graphics, space and colour to help a particular audience understand a message. Both matter: high technical quality cannot rescue a confusing design, and a beautiful layout cannot restore details that were never captured.

BLISS example

A book-fair poster must make the date, venue and call to action easy to identify. A large decorative photograph with tiny grey text may look attractive but fail its purpose.

BRIM example

An archival exhibition needs a readable access image, a trustworthy caption and clear source identification. Enlarging a small, blurred thumbnail does not recover missing details in the original capture.

2.2 Digital images: pixels and raster representation

A raster image is organised as a rectangular grid of picture elements called pixels. Each pixel stores or represents a colour or tonal value. An image measuring 1200 × 800 pixels contains 960,000 pixel positions, or approximately 0.96 megapixels. The image dimensions describe the number of pixels, not the physical size of a print.

A small raster illustration — individual cells represent pixels

This deliberately small 8 × 8 illustration becomes blocky when enlarged because its cells become visible.

Raster files are well suited to photographs, scans and images containing complex tonal variation. When enlarged beyond the available information, they can appear soft or blocky. This is called pixelation. Editing software may interpolate new pixel values to enlarge an image, but interpolation does not recreate the original source detail with certainty.

2.3 Vector graphics: shapes rather than fixed grids

A vector graphic represents content using mathematical descriptions of lines, curves, shapes, fills and strokes. When a true vector is scaled, the renderer recalculates the shapes at the new size. This makes vectors particularly useful for logos, icons, diagrams, maps with simple features and information flowcharts. Typical formats include SVG and vector content in PDF documents. A PDF can also contain raster images, so its extension alone does not guarantee vector content.

Key distinction: vector does not automatically mean a better choice. A photographic scan of a historic letter is better treated as a raster capture; a navigation icon can be drawn as vector graphics.

2.4 Pixel dimensions, image resolution, PPI and DPI

These terms are related but should not be used interchangeably.

  • Pixel dimensions: the width and height of a raster image in pixels, such as 2400 × 1600 px.
  • Pixel count: width × height. A 2400 × 1600 image contains 3,840,000 pixels (3.84 MP).
  • PPI (pixels per inch): the density at which image pixels are mapped to physical dimensions in an intended print or capture workflow. It relates pixels to inches.
  • DPI (dots per inch): usually refers to physical dots placed by a printer or similar output device. A printer may use multiple ink dots to represent one image pixel.
  • Screen display size: depends on browser layout, device scale and pixel density; changing embedded PPI metadata alone normally does not increase image detail in a web page.
Print width (inches) = image width (pixels) ÷ desired PPI

Worked example: a 2400-pixel-wide photograph used at 300 PPI has an intended print width of 2400 ÷ 300 = 8 inches (about 20.3 cm). The same data printed at 150 PPI spans 16 inches, but with fewer source pixels per inch. This is a planning relationship, not a promise of print sharpness: capture quality, focus, output device and viewing distance still matter.

Important for digitisation: a suitable scanning PPI depends on the physical dimensions, condition, detail and intended use of the original. There is no universal scanning resolution that is correct for every material. Technical digitisation standards are introduced more fully in Unit 8.

2.5 Aspect ratio and resizing

The aspect ratio expresses the relationship between width and height. A 1920 × 1080 image has a 16:9 ratio; a 1200 × 800 image has a 3:2 ratio. Keeping the aspect ratio prevents distortion when resizing. Cropping removes parts of an image to fit a new shape. Stretching changes the proportions and may make people, lettering or artefacts appear wider or taller than in the source.

2.6 Colour models and why colour changes between devices

Digital imagery requires a way to express colours numerically. A colour model specifies the components used to describe colours, while a colour space gives those values a more precise interpretation.

RGB — additive colour for displays

In RGB, red, green and blue light are combined. A common 8-bit-per-channel RGB pixel uses a value from 0 to 255 for each channel: RGB(255, 0, 0) represents red, RGB(0, 0, 0) black and RGB(255, 255, 255) white in a typical RGB representation. Screens emit or modulate light, making RGB a natural model for web and screen-based work.

CMYK — subtractive ink model for print

CMYK refers to cyan, magenta, yellow and key (black) inks. The inks absorb portions of incident light. Commercial print workflows may use CMYK, but converting colours between RGB and CMYK is not a simple one-to-one replacement of channel numbers. Available colours depend on inks, paper, printer and colour profiles.

Grayscale and other representations

Grayscale represents brightness or tonal values without full colour; it can be useful for certain source documents or line-art workflows. HSV/HSL organise colour by hue, saturation and value/lightness for convenient selection in design tools. They do not replace formal colour-managed output spaces.

Colour profiles

Colour profiles help software interpret and transform colour values between devices. sRGB is a commonly used colour space for web images. When colour fidelity matters—such as documenting the hues of a historical textile—retain source information, use consistent capture conditions and document relevant profile and editing choices. Avoid making preservation claims from a visually pleasing screen display alone.

2.7 Bit depth and what it means for colour

Bit depth describes how many bits are used to represent tonal or colour information. In a common 24-bit RGB image, three channels each store 8 bits; therefore each channel has 2⁸ = 256 possible integer levels. The combination permits up to 256³ = 16,777,216 channel combinations, without implying that any device can show every colour equally well.

A 16-bit-per-channel workflow provides more possible tonal levels for editing and can help avoid visible banding during substantial adjustments. Not every output format or viewer supports the same precision, and higher precision often increases storage requirements. Bit depth is different from pixel dimensions: increasing one does not automatically increase the other.

2.8 Estimating uncompressed image data size

File size depends on pixel dimensions, bits per pixel, compression, metadata and container format. To estimate the pixel payload for an uncompressed image without row padding or extra information, use:

Approximate bytes = width × height × bits per pixel ÷ 8

Example: a 1920 × 1080, 24-bit RGB image has an estimated 1920 × 1080 × 24 ÷ 8 = 6,220,800 bytes of uncompressed pixel data, or about 5.93 MiB. A real PNG or JPEG will usually have a different file size because compression, metadata and other structures affect storage. JPEG compression is commonly lossy, whereas PNG compression is lossless for its represented pixel data. Unit 6 explains compression in detail.

Why this matters: a collection of thousands of high-resolution scans can create a substantial storage and backup requirement. Do not rely on a rough calculation as the final preservation storage plan: account for versions, metadata, checksums, redundancy and future growth.

2.9 Visual communication: the message comes first

Visual communication deliberately uses layout, colour, typography and graphics to help users notice, understand and remember information. A design must answer: Who is the audience? What must they find or do? Which information is essential? What are the reading conditions?

For a library poster, the primary information may be an event title, date, venue and action. For an archival record display, the primary information may be the item name, date, provenance, what the displayed image represents and how to consult the full description. If secondary decorations attract more attention than these facts, the design hierarchy needs revision.

2.11 Typography for reading, scanning and emphasis

Typography is the choice and arrangement of written characters. A typeface is a family of letter designs (for example, a serif or sans-serif family); a font is a particular style or implementation within that family.

  • Serif typefaces include small finishing strokes. They can work well for some long-form printed reading contexts.
  • Sans-serif typefaces omit those strokes and are commonly used for clear interfaces and screen-based headings.
  • Font size must suit medium, viewing distance and audience. A slide projected in a large classroom needs different sizes from a mobile web page.
  • Line length and line spacing affect reading comfort; very long dense lines are tiring, and excessive line spacing can break the reading flow.
  • Emphasis should be selective: bold text helps identify key terms, but entire paragraphs in capitals or multiple coloured fonts reduce clarity.
  • Images of text are often harder to resize, select, translate or access than real text; prefer actual text when possible.

2.12 Colour contrast and inclusive visual design

Colour can communicate relationships, categories and emphasis, but colour must not be the only way to communicate meaning. A red/green status chart should also include labels or patterns. Users may experience colour-vision differences, low vision, glare, small displays or low-quality projections.

Under WCAG 2.2 Success Criterion 1.4.3 (Level AA), normal text usually needs a contrast ratio of at least 4.5:1; qualifying large text needs at least 3:1, with stated exceptions. Meeting the numerical threshold is a baseline, not a guarantee that all users can read the content comfortably. Other visual and interface requirements also apply.

The interactive contrast checker in the course website computes contrast between two selected solid colours. It is a learning demonstration, not a complete accessibility audit.

Use this check in a real project. Read the poster at normal size, test it on a smaller screen, examine the labels without relying on colour, and ask an intended user to find its important information.

2.13 Layouts and information hierarchy

A layout is a deliberate arrangement of text, imagery, space and controls. A common reading-friendly hierarchy for an information poster is (1) clear title, (2) essential message, (3) date/place or item identity, and (4) supporting details. The layout should keep relationships visible: a caption belongs near its image, and a citation or archive identifier should not become visually detached from the resource it describes.

Gestalt ideas in simple terms

People tend to perceive nearby elements as related (proximity), visually similar elements as a group (similarity), and content aligned along a path as connected (continuity). These tendencies can help structure menus, thumbnail galleries, catalogues and digital exhibitions. They should never override clear written labels or an appropriate reading order.

Responsive design means adapting the layout to different devices. A three-column desktop gallery may need to become a single column on a phone. Critical text must remain legible without zooming horizontally, and controls need sufficient space for touch and keyboard use.

2.15 A systematic visual design workflow

  1. Define the user task. A poster should help users decide to attend; an exhibition card should help users interpret a historical source.
  2. Inventory the source material. Check image quality, permissions, dimensions and accuracy of captions.
  3. Choose an output. Website, printed poster, presentation, kiosk or mobile resource.
  4. Plan information hierarchy. Draft the wording before applying decorative treatments.
  5. Choose appropriate graphics. Use raster for photos and scans, vector for simple icons and scalable diagrams.
  6. Establish typography and colours. Keep a small consistent set and check contrast.
  7. Prepare deliverables. Retain source originals, make appropriate access versions, and record edits.
  8. Evaluate. Test reading order, contrast, small-screen appearance, file size and user success.

2.16 Worked example — choosing an image for a public exhibition

A scanned image of a historical document measures 2400 × 1600 pixels. The team wishes to show it on a 1200-pixel-wide webpage and in a printed educational handout.

  1. Count the information: 2400 × 1600 = 3.84 million pixels, enough to prepare a smaller web derivative without inventing new detail.
  2. For the website: create an access image around the display requirement, retaining the aspect ratio. Offer a zoomable version if fine text must be read and access rights permit it.
  3. For print: at 300 PPI, the 2400-pixel dimension corresponds to about 8 inches. Assess the material and intended use before deciding whether this is sufficient.
  4. Preservation: protect the source/master image and retain capture information. Do not overwrite it with the resized public image.
  5. Context: caption the displayed image accurately, and distinguish it from the complete source if cropping is applied.

2.17 Common misconceptions to correct

  • “300 DPI automatically means a sharp image.” — No. Actual source pixels, focus, physical output and printer characteristics also matter.
  • “Changing PPI in file properties adds detail.” — No. It changes an intended density relationship unless pixels are resampled.
  • “A vector logo and a photograph should always use the same file format.” — No. Choose based on content, workflow and delivery.
  • “More colours always means better communication.” — No. Colour accuracy and clear hierarchy matter more than visual abundance.
  • “A pretty archival image is automatically faithful.” — No. Documentation and responsible handling still matter.
  • “Colour alone can label urgent items.” — Not reliably. Add text or other non-colour cues.

2.18 Summary and preparation for Unit 3

Images are represented as grids of pixels or as shapes and paths. Pixel dimensions, bit depth and compression influence technical use and storage. PPI concerns a physical density mapping; DPI generally concerns output dots. Colour depends on representation and device conditions. Typography, hierarchy, contrast and spacing influence whether people can understand and use the information. In Unit 3, you will apply these foundations to image capture, file formats, editing workflows and OCR.

Remember: Choose the representation for the content, the design for the user, and the workflow for authenticity and long-term responsibility.
